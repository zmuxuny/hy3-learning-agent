# 官方 Demo 录制脚本

目标 Issue：<https://github.com/Tencent-Hunyuan/Hy3/issues/4>

官方硬性要求是：全程通过 API 使用 Hy3、至少一个交互前端、至少两条端到端 Demo、视频或 GIF 总长不超过 2 分钟、项目开源且 README 写明 Hy3 的角色。下面的脚本按 **115 秒上限** 设计，留出 5 秒编码余量。

## 录制前冻结状态

1. 停止正在运行的 `./scripts/start.sh`。
2. 运行 `./scripts/demo-data.sh reset`。脚本会把数据库、上下文快照和工作区整体移动到带时间戳的 `data/backups/`，不会删除 `.env` 或原数据。
3. 运行 `./scripts/start.sh`，打开 <http://127.0.0.1:8000>，确认侧栏没有历史计划和 Session。
4. 运行 `./scripts/demo-preflight.sh`；再在“收件箱”执行 SMTP 与 IMAP 连接测试。邮箱镜头是增强项，不应遮挡站内提醒主线。
5. 浏览器缩放 100%，建议录制 1920×1080 或 2560×1440，隐藏书签栏、终端密钥和系统通知中的私人信息。
6. 完整排练一次后，停止服务并复制 `data/learning_companion.db` 到被 Git 忽略的 `data/demo-checkpoints/`。正式录制失败时可恢复检查点，不必用伪造数据冒充 Hy3 输出。

## Demo 1：从模糊目标到可执行计划（0–52 秒）

**起点：** 空白个人工作台。**终点：** 一份经用户确认、包含具体资源和证据要求的正式计划，以及承接该计划的连续 Session。

预先把下面这句话放进剪贴板：

> 我想在 7 天内学会 FastAPI，并做出一个真的能运行的 Agent Harness。先不要直接生成计划，请先判断还缺什么信息，搜索并核验适合项目实战的具体课程或教程。

录制镜头：

1. **0–6 秒**：从空白对话页输入目标，画面同时出现“Hy3”和运行状态。
2. **6–18 秒**：展开最新工作记录，快速展示 `planning_intake_*`、规划子 Run、`web_search/web_open`；不要停留在长 JSON。
3. **18–28 秒**：直接在提问卡填写“有 Python/FastAPI 基础、每天 90 分钟、产出可运行项目、核心任务必须有代码或测试证据，第一项核心任务安排为可运行的最小工具调用循环”，提交后卡片原位完成。
4. **28–42 秒**：展示可审阅计划提案：阶段、任务、总时长、具体学习资源和为什么适合；点击“采用并创建计划”。
5. **42–52 秒**：点击“在计划中继续”，展示 `SessionPlanLink + handoff_summary` 形成的显式上下文转场，以及计划详情的纵向时间线。

录制重点：Hy3 不是一次 API 问答，而是在统一 Runtime 中澄清、委派、搜索、观察工具结果和产出提案；正式 Plan 只有用户采用后才写入。

## Demo 2：知道进度、检查成果并主动跟进（52–105 秒）

**起点：** Demo 1 创建的计划。**终点：** Agent 基于当前进度推进一个任务，验证真实文件或代码证据，更新计划并产生后续复习/提醒。

录制前把仓库内明确标注的示例提交物复制到个人工作区；它是真实可运行的用户证据，不是预制模型输出：

```bash
mkdir -p data/workspace/demo
cp examples/demo/minimal_agent.py data/workspace/demo/answer.py
python data/workspace/demo/answer.py
```

预先准备两句输入：

> 先读取我在这个计划里的真实进度，教我当前下一步；只讲现在需要的内容，并给我一个最小练习。

> 我完成了当前核心任务，证据在 demo/answer.py。请读取并运行它，按任务要求验收；通过后更新进度并安排一次复习。

录制镜头：

1. **52–65 秒**：在计划 Session 发送第一句，展示 `study_state_get` 读取计划版本、当前任务、证据缺口和复习状态，再给出一任务式教学。
2. **65–82 秒**：发送第二句，展开工作记录，展示 `file_read → code_execute → submission_create → submission_check → review_schedule`。如果证据不合格，保留真实拒绝并使用修正后的文件重试，不剪成虚假成功。
3. **82–92 秒**：切回计划页，展示进度、XP、任务证据和复习时间已经更新；打开运行抽屉展示工具输入/输出与可撤销操作。
4. **92–105 秒**：在收件箱点击“立即检查”，展示全局心跳通过同一 Runtime 读取到期任务/复习并决定提醒或保持安静。出现站内消息时展示归档与恢复；若 Guard 判断静默，则展示它的可审计静默理由。

录制重点：计划上下文、Session 原始消息、分层记忆和事件账本共同让 Hy3 知道用户当前在哪里；证据门槛由后端 Guard 强制，不靠模型口头承诺。

## 收尾（105–115 秒）

- 快速扫过工具契约页或运行抽屉，字幕标明“37 个输入/输出双向类型化工具，SQLite + Markdown 快照”。
- 定格 GitHub 项目地址和一句话：`A personal learning agent harness powered by Hy3 API.`
- 不展示密钥、邮箱授权码、完整个人邮箱、数据库原始内容或私有对话。

## 剪辑与真实性规则

- 可以删等待、倍速和跳转，但两条流程都必须让观众看清“输入 → Hy3/工具行动 → 可验证结果”。
- 不把自动化测试替身、固定夹具或手写数据库记录冒充真实 Hy3 调用。
- 不展示模型私有思维链；展示面向用户的状态摘要、工具调用、结果、错误与恢复即可。
- Web 或模型偶发超时时，保留一次简短失败与可观察重试即可，不要让长等待占满 2 分钟。
