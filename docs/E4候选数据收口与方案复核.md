## 对两份方案的复核

### 保留的核心方向

项目方向符合任务一：给真实技术学习场景提供可运行 Hy3 应用，评价其 Planning、Intervention、Assessment、Revision 决策。产品内验收用户作业，与第三阶段审查 Agent 验收决策，边界清楚。七维 Rubric、确定性硬约束、证据引用、四轨分别报告及失败单列值得保留。

### 已纠正的方案偏差

1. **冻结顺序。** E4 先产出候选；独立内容复核与 Development/Calibration 方法验证后，才固定正式协议、Benchmark 和 Primary 运行条件。E5 如修改 Judge/Prompt/Rules，必须产生可追溯的新协议身份，旧候选结果继续作为历史记录。当前来源包是保守超集，Judge 改动也会改变 Runtime 协议摘要，不能默默给旧输出换身份。
2. **反事实数量。** 12 个不同主题不是反事实对。Primary 每轨实际为标准 4、困难 4、边界 2、对抗 2；精确反事实实验另建独立 Development 家族，不再声称现有 Primary 包含 12 对/24 例。
3. **真实学习过程。** 当前 48 个输入是 12 组独立合成状态，不是跑完 12 段连续学习故事。验收报告是题目材料，不是实际 GPU 实验或真实用户学习成效。最终 Demo 仍需展示目标、采用计划、提交、验收和后续主动决策的连续闭环。
4. **实验优先级。** 任务书硬要求是判别力、一致性（人工一致或重复稳定性至少一种）、完整结果表、典型 Case 分析及不超过两分钟的 Demo；48/24、反事实数量、七项实验和 production registry 是内部承诺。优先闭合判别力与重复一致性，再做四轨正式评测、失败归因和 Demo。人工 Kappa、额外反事实及版本对比按独立标注和资源条件排期，不伪造或删掉失败来满足门槛。
5. **范围与时间。** 不恢复 M15–M20，也不在项目方案加入更多发布治理细节。排期改按“内容复核 → 方法验证 → 正式冻结与评测 → 报告/展示”的依赖推进；原 9 月 3–5 日已经完成所有数据与校准的日程不再作为完成事实。

### 仍需复核的科学有效性

作者给出的 Good/Mild/Severe 只有可控变异证据，尚无独立标签可靠性。8 个 Severe 命中 Rule Gate 只能证明这些反例被规则识别；Good/Mild 的语义差异要交给后续真实 Judge 与人工复核。Primary 的单一允许行动需要检查是否排除了合理询问、等待或审批行为，尤其是外部阅读后合法等待用户批准的 Planning。Primary 不参与 Agent、Prompt、Rules 或 Judge 调优；如根据其输出调整决策语义，须将这一轮标为探索记录，并另外确定未参与调优的测试材料。

## 剩余风险与下一步边界

**不能回答“所有审计问题都已修完”。** 表中问题已有修复与反例验收，但下面的事项尚未关闭：

- `primary-s04-r` 与 `primary-s10-r` 的两类引用错误已用独立 Runtime 反例修复，原真实批次仍保留失败。新版本没有付费重跑这两例，不能声称其真实重跑已成功。
- `primary-s06-p` 保留 `runtime.non_exportable_terminal` 和 3 次已完成模型调用。第三次输出达到 16,000 Token，两个工具参数均为 invalid_json；仅凭这些事实不能证明 Runtime 终止的唯一根因。当前失败导出仅给出通用终态摘要，缺少足够的安全终止细节。
- 72 个 Case/Oracle 以及 8 组三档质量标签都缺少独立人工内容复核；难度和合理行动边界不能由通过 Schema 或作者自检代替。

下一位实现者应先在 Development 临时 Case 中离线重放“输出截断/参数错误/Runtime 限额”路径，核对真实 RunEvent 与根 AgentRun 状态，补充经过脱敏的确定性终止原因；验收要求是完整保留已完成调用、未知参数不改写、准确分类、未执行工具不伪造为成功，并保持唯一终态与 non-formal。只有反例确定根因后才修改行为，不为单个 Primary 定制 Oracle 或自动重跑替换。正式冻结前必须完成这项归因。

硬杀 Worker 或进程超时可能丢失尚未落盘的调用前缀；账本仍保留费用预留，Failure 会阻止能力结论，不能声称所有异常均可完整回放。生产用户轨迹的自动提取、许可和脱敏复核流程尚未实证；当前不读取生产数据库来补数据。
