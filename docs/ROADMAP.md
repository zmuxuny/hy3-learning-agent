## M7：检索、耐久运行与交付

这是当前硬化与交付队列；产品优先级变化时以最新用户目标和 `STATUS.md` 为准，不把“唯一下一项”写死。按依赖顺序推进，避免在不可恢复的 Runtime 上扩大通用多 Agent：

1. **混合语义检索**：建立 Embedding Provider 接口和本地向量表；关键词/BM25、向量相似度、作用域、置信度与时间衰减分别产出分数，再使用可解释的加权融合或 RRF。用固定问题集验证召回率、跨计划隔离和无 Embedding 时的关键词回退。
2. **可恢复 Run 状态机**：为模型轮次、待执行工具、审批请求和上下文版本保存 Checkpoint；实现 `waiting_approval → queued → running`，启动时扫描并恢复未完成 Run。
3. **幂等与预算**：每个工具调用持久化 `idempotency_key`、输入哈希和提交状态；写工具重复调用返回原结果。Run 增加模型 Token、工具时间、网络次数与费用预算，超限产生可观察停止事件。
4. **浏览器后台通知**：注册 Service Worker、Notification/Push 订阅和离线点击路由；本地部署先支持页面关闭但服务仍运行时的系统通知，不能把电脑关机描述成可提醒。
5. **通用受限子 Agent**：在现有规划专用子 Run 基础上实现 spawn/status/join/cancel、工具白名单和结构化 Artifact；子 Agent 只接收最小上下文，默认只读，写操作回到主 Agent 审批与提交。
6. **邮件/通知设置页**：提供本地加密凭据保存、供应商预设、免打扰/频率/渠道策略、测试与删除凭据；设置 API 永不回传秘密。
7. **赛事交付**：冻结 Demo 数据和脚本，完成两条真实 Hy3 录屏、协作记录、安装/安全说明、GitHub 仓库与 `rhinobird2026` PR。发布前运行后端、前端、移动端、真实 Web 和可选邮箱验收矩阵。

验收门槛：检索结果可解释且计划隔离；中断进程后 Run 能从最后 Checkpoint 恢复且写操作不重复；审批可暂停并继续；子 Agent 不能绕过主 Agent Guard；Demo 仓库不含任何密钥或个人学习数据。

当前产品主线已完成“澄清 → 规划分工 → 提案 → 正式计划 → 跟踪/教学 → 消息修订”。下一项在录制真实 Demo 后根据暴露的问题，从混合语义检索或可恢复 Run 状态机中选择；不得跳过 Demo 验收直接宣称交付完成。
