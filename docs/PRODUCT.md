# 产品定义

## 一句话描述

Learning Agent 是一个会持续维护学习上下文、主动判断是否需要介入，并通过资源、计划、证据检查、提醒和复习帮助用户真正执行计划的个人 AI Harness。

产品只面向个人电脑或个人服务器持续运行，不建设账号、组织和租户系统。首要场景是编程和技术学习。

## 核心问题

常见 AI 学习产品依赖用户主动打开对话。对话结束后，模型不了解计划是否执行、用户在哪里受阻、什么知识应该复习，也不会主动检验学习效果。

本项目解决三个问题：

1. **计划与执行脱节**：计划必须随真实进度演进。
2. **AI 永远被动**：系统持续观察状态，并决定何时保持安静、提醒或抽查。
3. **上下文容易丢失**：用户偏好、各计划状态、历史表现和原始对话需要分层管理。

## 核心闭环

```text
建立目标和用户画像
        ↓
Hy3 生成结构化计划
        ↓
用户执行任务并产生学习事件
        ↓
后台 Agent 周期性读取状态和记忆
        ↓
观察 → 思考摘要 → 规划 → 调用工具 → 验证结果
        ↓
保持安静 / 提醒 / 抽查 / 调整计划
        ↓
更新事件、记忆与下一次检查时间
```

## 主动的含义

后台进程持续运行，但不无限循环调用模型。出现候选事件时才调用 Hy3：

- 任务临近截止或已经逾期
- 长时间没有学习活动
- 到达间隔复习时间
- 连续失败表明用户可能受阻
- 提前完成，计划有调整空间
- 用户允许的学习时间到来
- 多个计划出现时间或优先级冲突

Hy3 读取经过组装的上下文并自主决策。系统再经过冷却时间、免打扰时段和频率限制决定是否触达用户。

## 自主权模型

Agent 可以通过基础工具直接操作计划。所有写操作必须产生版本、审计记录和可执行的逆操作。

- **自动执行**：提醒、抽查、安排复习、创建通知、生成临时学习材料。
- **自动执行且可撤销**：调整任务时间、创建补救任务、重排低风险任务。
- **执行前确认**：删除数据、跨计划大规模重排、改变最终目标、写入全局长期记忆、向外部服务发送敏感内容。

用户以后可以提高自治等级，但不能关闭操作审计。

## 学习计划

创建计划时收集：学习目标、当前基础、最终期限、每周可用时间、学习偏好、期望产出、可用资源和不希望采用的学习方式。

计划采用：

```text
Plan
└── Stage
    ├── 学习任务
    ├── 学习资源
    ├── 练习
    └── 阶段考核
```

系统支持多个并行计划，由 Agent 协调时间和优先级。学习材料可以来自用户文件、联网搜索或 AI 生成内容。

## 主动考核

首批支持：

- 简答和追问
- 编程任务或文件提交
- 阶段综合考核

普通任务允许手动完成；核心任务必须提供证据或通过考核。评分保留题目要求、用户证据、判定依据和后续建议。错误处理由 Agent 自主选择提示、追问、补救任务或间隔复习。

## 上下文与记忆

系统保存原始对话，也生成短期和长期摘要。上下文分为：

- 当前 Run 的工作记忆
- 会话原文与会话摘要
- 不可变学习事件
- 每个计划的独立记忆
- 跨计划全局短期记忆
- 经确认的全局长期画像

数据库存储结构化事实，同时生成可读 Markdown 快照。用户可以在“AI 眼中的我”页面查看、纠正和删除记忆，并追溯每条记忆的来源。

## 通知渠道

站内收件箱是默认渠道；浏览器通知和 SMTP 邮件按需开启。启用 IMAP 后，邮件回复通过线程令牌转换为 `email_reply` Agent 事件。

应用关闭或主机停机时不保证提醒；用户需要让本地服务持续运行。

## Harness 体验

Harness 不是一组“按钮 + Prompt + 固定工具流”。用户消息、后台心跳、任务事件、复习到期和后续邮件回复进入同一个长期运行的 Agent Runtime。Agent 自己选择上下文、制定多步行动、调用基础工具、观察结果并在必要时纠错；确定性 Guard 只负责权限、频率、预算和安全边界，不替模型写死业务工作流。

前端以 Session 为连续对话主画布和侧栏导航单位：一个 Session 可以拥有多次 Run，后续追问追加到现有消息流，不会让每条消息在侧栏生成一个伪对话。首轮完成后生成简短语义标题，用户可手动改名且手动标题不会再被自动覆盖。每个 Run 的上下文组装、进行中的工具和结果嵌在触发它的用户消息之后；完整参数、返回值、失败和撤销入口放在可收起的运行抽屉中，不展示模型私有思维链。运行期间不并发接受同一会话的下一条输入，用户可以先停止当前 Run。

全局对话创建计划后仍保持全局作用域，并显示显式承接卡片。用户选择“在计划中继续”时建立新的计划 Session，通过来源关系与交接摘要继承必要决定，而不是修改原 Session。对话和计划都可以归档、查看归档列表并恢复；归档不等于删除。

计划页面是 Agent 的可操作环境而不是旁路 CRUD 后台。信息架构分为两层：学习计划首页用完整卡片列出所有目标、进度、期限和 Agent 操作概况；点击卡片后进入单一计划工作区，沿纵向时间线查看阶段、任务、证据、复习和操作痕迹。详情不使用横向 Kanban 方格，也不常驻计划列压缩内容；计划路径和 Agent 输入框共享同一视觉中轴。用户从任务行发起的请求仍回到统一 Runtime，由 Agent 先读取上下文再决定是否使用工具。

对话焦点必须显式，不由“最近加载过哪份计划”暗中推断：

- **全局对话**不绑定 `plan_id`，Agent 读取全局画像与跨计划状态，并可通过工具协调多个计划。
- **计划对话**绑定明确的 `plan_id`，Agent 优先读取该计划的任务、事件、记忆、证据和复习安排。
- 进入计划工作区会显示计划焦点；“新对话”始终回到全局焦点。浏览列表、后台刷新和 Run 完成都不能偷偷改变当前页面或焦点。
- 切换焦点使用新的会话边界，避免一个计划的近期原始对话无意进入另一计划；有价值的跨计划结论仍需通过全局记忆候选提升。

统一 Agent 直接完成资源调研、代码评测和计划维护；主 Runtime 始终负责证据、权限判断和最终写操作。

## 视觉与游戏化

界面采用 ChatGPT/Codex 桌面端风格的专业工作台：浅色侧栏、大面积留白、克制边框、悬浮输入框和按需打开的运行抽屉，并加入轻游戏化：

- GitHub 风格学习热力图
- XP、等级和连续学习天数
- 固定规则与 AI 个性化徽章
- 计划进度环、纵向时间线和学习日历
- 跨计划技能树

奖励优先来自有证据的学习行为和考核结果，而不是简单点击。

## 参赛 MVP

### Demo 1：计划与主动提醒

用户创建完整计划。后台心跳读取计划、用户偏好和近期事件，Hy3 自主决定保持安静或发送带具体下一步的提醒。前端展示完整 Agent Run。

### Demo 2：主动抽查与调整

用户完成核心任务后，Agent 安排并在复习时间主动出题。Hy3 按证据评分，系统更新薄弱点和复习时间，并通过工具调整计划；修改可追踪和撤销。

## 不属于参赛 MVP

- 文字游戏、拍照热量和社区功能。
- 云端多租户、团队协作和移动推送。
- 图片徽章和真实多子 Agent 编排。
- 用无限增长的 Prompt 代替上下文管理。
