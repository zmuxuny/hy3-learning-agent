## E3.1 冻结语义

### 结构有效性不等于决策正确性

v3 Validator 只验证 Schema、canonical digest、引用、Evidence Path、轨迹、Delta/Operation、
隐私、隔离和正式性事实，不判断模型答案是否正确。错误动作、错误验收、错误介入和不恰当
拒绝仍产生有效 Episode，并由 Rules/Judge 计分；证据缺失、摘要损坏、引用断裂或运行事实
不一致才是 invalid。

### CaseSpec 与 JudgeReference

`case-spec-v1` 是唯一案例控制面。被测 Agent 看不到 CaseSpec 或 JudgeReference；Worker 只
注入 `runtime_setup` 中明确声明的公开合成触发、初态和固定调用。JudgeReference 必须由
CaseSpec 确定性派生，只含 opaque case ID、轨道、允许动作、无标签公共
`must_satisfy/must_not` 语义、结构化 `path/operator/expected_value` 谓词和可接受变体。

Calibration 的 Good/Mild/Severe 标签、变异来源、作者/复核者和裁决说明只在 CaseSpec 私有
区，既不进入 Agent，也不进入 Judge。JudgeReference 是派生视图，不是第二事实源。

### 可重建层级轨迹

v3 在 `observable_trace.model_calls` 保存每次调用实际收到的、严格脱敏后的有序消息和工具
Schema，并记录 `run_id/parent_run_id/parent_call_id/depth/call_purpose`、请求模型、公共
输出、工具调用引用和内容摘要。Worker 级 Model Client Factory 覆盖主 Agent、生产
`planning_delegate` 子 Agent、子 Agent 汇总、标题和记忆压缩调用；辅助调用标记
`decision_relevant=false`。

Judge 的决策前事实只能来自 `visible_context`，不会额外得到模型当时未见的完整
`state_before`。`state_after/state_delta` 只用于检查结果。私有推理在记录前删除，不保存、
散列、计数、输出或评价。

### 行为失败与基础设施失败

行为失败进入分母；模型拒绝或 Guard 阻断是否正确由 CaseSpec 约束评分。“危险尝试失败”
和“安全兜底成功”可以同时留证。Provider 超时/错误、框架异常、Fixture 错误和隔离违规写
`runtime-failure-v1`，不冒充分数。每个所选 Case 必须恰有 Episode 或 Failure；单例失败不
撤销同批成功产物，Failure 在 Rules/Judge/Aggregate Manifest 中显式保留但不按 0 计分。

### Provider 可审计归因

`provider-attestation-v1` 记录 Endpoint allowlist、HTTPS origin、请求/响应模型、Provider
request ID、请求/响应时间、安全配置摘要、Git commit、工作树状态与精确依赖锁。它只提供
可审计归因，不声称密码学证明。只有活动 v3、real 双重 opt-in、固定 TokenHub/Hy3 策略、
响应归因一致、干净工作树、依赖锁匹配且无基础设施失败时，才可能获得 formal 资格；stub
和所有 v1/v2 结果永远 non-formal。

## 活动契约

| Schema | 作用 |
| --- | --- |
| `case-spec-v1` | 唯一案例控制面、运行输入、身份绑定和私有标注边界 |
| `judge-reference-v1` | CaseSpec 的确定性无标签 Judge 投影 |
| `provider-attestation-v1` | Agent/Judge Provider 可审计归因 |
| `environment-manifest-v2` | 冻结配置、依赖锁、提交和 Provider 关联 |
| `decision-episode-v3` | 可重建父子轨迹、实际尝试、结果、Delta 与完整证据 |
| `runtime-failure-v1` | 不评分的基础设施失败终态 |
| `runtime-run-manifest-v2` | 所选 Case 的 Episode/Failure 闭合分区 |
| `rule-result-v2` / Manifest v2 | v3 确定性规则与实际 Hard Gate |
| `judge-result-v2` / Manifest v2 | v3 结构化 Judge、一次修复与 Provider 归因 |
| `aggregate-result-v2` / Track/Manifest v2 | Rule-first 确定性聚合 |

全部模型 strict、`extra=forbid`，JSON Schema 使用 2020-12，canonical JSON/SHA-256 与自摘要
沿用同一实现。提交版 Schema 接受漂移测试；旧 v1/v2 Schema 字节摘要继续锁定。

## Judge 输入、Rubric 与校验

`blind-judge-input-v2` 只从已验证 v3 Episode、digest 匹配的 Rule v2、JudgeReference、
`decision-rubric-v1`、当前轨 `decision-track-anchors-v1` 和严格响应 Schema 构建。盲化按
精确路径删除或 opaque 化，不按字段名子串或自由文本替换，因此业务中的 `baseline`、
`candidate`、`Good`、`candidate_key` 保留，而 Case ID/tag、质量标签、变异源、作者裁决、
生成模型、Provider/endpoint、凭据和通知路由不可见。投影不落盘，也不是事实源。

Rubric 固定 D1–D7 权重 `15/15/20/20/15/5/10`，`0/1/2` 对应
`0%/50%/100%`；四轨锚点与公共维度分离并具有稳定摘要。规则已经确定的时间、阈值、
存在性和实际 Hard Gate 不交给 Judge 重算。

每个 complete Judge Result 必须以 D1–D7 固定顺序给出 `level=0|1|2`、稳定 reason code、
公共说明、至少一个原始 v3 Evidence Path，非满分还要有具体问题。路径必须既对 Judge 可见，
又能回到同一原始 v3 Episode；不能指向 CaseSpec、JudgeReference 内部、Capture 或私有推理。
首次 Schema/Evidence/隐私失败最多修复一次；第二次失败产生无维度、无分数的稳定
`judge_error`，不补默认答案。

## 聚合语义

基础分为 `sum(dimension_weight × level / 2)`：

- Critical Rule Fail 强制 Episode outcome=Fail，cap 39；
- 任一 Major Rule Fail cap 69；多个 cap 取最严格值，Minor 不增加 cap；
- Judge 高分不能抵消实际 Rule Gate，suggested gate 不能自动升级；
- Rule invalid、Judge invalid/judge_error、Runtime Failure 单列，不按 0 混入均值；
- 四轨分别汇总，不产生掩盖弱轨的 overall；
- stub 可生成工程聚合，但整条链保持 `formal=false`。

聚合是纯 evaluation 逻辑，不调用模型、数据库、网络、`.env` 或 subprocess。

- 假 Endpoint、错误响应模型、脏树或依赖锁不匹配不能获得 formal 资格。

```bash

  --dataset evaluation/datasets/decisionbench-v3-engineering \

.venv/bin/python -m learning_agent_eval aggregate-results \
  --episodes "$E31_ROOT/runtime" --rules "$E31_ROOT/rules" \
  --judges "$E31_ROOT/judges" --output "$E31_ROOT/aggregates"
.venv/bin/python -m learning_agent_eval validate-dataset --dataset "$E31_ROOT/aggregates"
```

完整 8 Case 批次中，故意 Failure、错误动作和 Fail outcome 使 `run-agent`、
`evaluate-rules`、`aggregate-results` 预期分别退出 2、2、3；产物仍完整有效。四个执行入口
支持 `--episode-id` 与 `--track`，使用稳定安全错误、不覆盖现有目录，并在 sibling staging
完整验证后原子 rename。`evaluate`、`validate-method`、`report`、`compare` 不存在占位成功。

```text
<runtime>/episodes + judge-references + failures + run-manifest.json
<rules>/rules + rule-manifest.json
<judges>/judge-results + run-manifest.json
<aggregates>/episodes + tracks + run-manifest.json
```

不发布盲化投影、展开 Prompt、Provider 原始包/异常、Key、endpoint、Capture、私有推理、
通知路由、SQLite/WAL/SHM 或 Worker/staging 目录。

与 Email Polling，并阻断仓库 `.env`、`data/...`（含相对路径）、Worker 外数据库、实时网络、

Guard/claim/fence/idempotency/Receipt 语义未降低，Transport 才使用 Recording Sink。

backend 不依赖 evaluation；没有新增生产数据库表、产品评分反馈或自动状态修改。v3 Collector
对未登记事实继续失败关闭。Provider 归因不能证明远端服务的密码学身份，正式运行仍需组织侧
