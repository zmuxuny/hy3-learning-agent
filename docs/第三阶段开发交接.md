## E1 已落地的链路

```text
E1 Runtime Mini Fixture
→ 父进程最小环境白名单
→ 独立 Worker + 临时 SQLite
→ frozen UTC + deterministic fixture identity
→ 生产 AgentRuntime + 生产工具
→ Evaluation Model Recorder
→ Guard / Intervention / Notification / OutboxAction
→ Recording Delivery Sink
→ OutboxReceipt
→ E1-only DecisionEpisode v1 projection
→ E0 privacy/schema/digest validator
```

Planning、Intervention、Assessment、Revision 各有一个公开合成、版本化 Fixture，固定时间、时区、逻辑 ID 和 scripted tool-call ID；Oracle 保存在独立文件，绝不进入模型可见 Context。常规验收通过生产 Runtime 和生产工具协议，只把模型 Provider 响应固定下来。

父进程不静态导入 `app.*`。Worker 在导入生产应用前设置失败关闭的 evaluation 配置：不读仓库 `.env`，不复制父进程全部环境，数据库必须是 Worker 内的绝对 SQLite，Scheduler 和邮件回复轮询必须关闭。它不启动完整 FastAPI lifespan，显式执行迁移、Fixture seed、Runtime、Sink drain、投影与原子发布；失败不会回退生产配置，也不会发布半成品。

## Fake Outbox 与渠道语义

E1 文档中的“假 Outbox”严格指：

```text
生产 notification_send
→ 生产 Notification Guard
→ 生产 Intervention / Notification
→ 生产 OutboxAction claim / fence / idempotency
→ Recording Delivery Sink
→ 临时库的确定性 OutboxReceipt
```

带类型 Adapter 注入点位于 `dispatch_action` 原本调用 SMTP/Web Push Provider 的最后边界；未显式传入 Adapter 时生产路径保持原行为。Sink 只接受 SMTP 和 Web Push，其他 destination 失败关闭，不执行 workspace file、subprocess 或未知副作用。

SMTP Receipt 保持 `accepted`、OutboxAction 可进入 `delivered`；Web Push 保持现有 `delivered` 语义。Response 声明 `transport=evaluation_sink`、模拟 destination、`external_side_effect=false` 和稳定版本。Agent 仍只看到生产 `notification_send` 的 `pending_delivery`，模拟 Receipt 不会注入后续模型消息。IMAP 仅被禁用和设陷阱，不存在假 IMAP Transport。

## 时间、资源、Recorder 与隐私

- `frozen_utc` 是作用域 ContextVar seam，默认仍是真实 UTC；E1 的 Runtime、Guard、通知冷却/安静时间、关键模型默认和工具路径共享冻结值，退出作用域恢复真实时钟。
- Snapshot Provider 只响应 Manifest 登记的 query/URL；未知搜索、Open 或 `resource_save` 校验结构化失败，不回退实时 HTTP/DNS。stub 模式阻断全部网络；real 模式也只能让显式模型 Provider 联网。
- Recorder 包装现有 `AgentRuntime.client`，不需要让生产 Runtime 反向依赖 evaluation。它透明支持 stream/non-stream，记录公开 visible messages/output、system/tool digests 与 Function Call；system message 正文不发布，只保留稳定占位与 version/digest。
- `reasoning_content`、`reasoning` 和 Chain-of-Thought 同义字段在 Recorder 投影前递归丢弃，不复制、不缓存、不散列、不计数、不导出、不评价。投影及最终产物再经 `privacy_issues`；私有推理 sentinel、凭据、认证 Token、非保留域邮箱、手机号或身份字段会令整次运行失败。
- Sink 不保留收件地址、Push endpoint/keys、认证信息或完整敏感载荷；数据库摘要只针对 Worker 内合成库的规范化逻辑投影，禁止读取或散列真实库。

## 运行入口

```bash
E1_OUTPUT="$(mktemp -d)/e1-output"
.venv/bin/python -m learning_agent_eval run-agent \
  --dataset evaluation/datasets/decisionbench-v1 \
  --manifest evaluation/datasets/decisionbench-v1/manifests/e1-mini-stub.json \
  --output "$E1_OUTPUT"
.venv/bin/python -m learning_agent_eval validate-dataset \
  --dataset "$E1_OUTPUT"
```

支持 `--episode-id` 与 `--track` 过滤，默认 stub。real 模式必须同时传 `--model-mode real`、`--allow-real-model` 并由调用者环境提供 `OPENAI_API_KEY`；Key 不进入 CLI 参数、Manifest 或产物。未经单独授权不要执行会产生费用的 smoke。

## 下一切片：E2

E1 的 `runtime_export.py` 是四个 Mini Fixture 专用的最小投影，不是通用导出层。E2 应在保持 v1 契约或显式发布新版本的前提下完成：

1. 通用 Episode Exporter 与跨场景身份映射；
2. 通用 Normalizer 和完整 State Delta；
3. Rules/Hard Gate 与字段级 Evidence Path；
4. 完整性检查，以及模型尝试、Guard 决定和最终状态的分层表达。

E2 仍不要提前实现 Hy3 Judge、聚合/报告、正式分数、Primary/Calibration 全量数据或反馈进产品。若真实生产状态无法由 DecisionEpisode v1 表达，必须先提供字段级冲突证据，并比较“保留 v1 + 内部 Capture Artifact”和“发布新 Schema 版本”两种方案，不能静默改写 v1。
