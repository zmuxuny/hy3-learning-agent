# E8 案例与展示材料

本稿整理可直接用于分析报告和展示的历史案例、两分钟脚本与本地拟发布清单。依据两份第三阶段方案及仓内[实战任务书](../../犀牛鸟开源-实战任务-混元大语言模型项目.pdf)第 1–2 页，选择任务 1「开放式场景：AI 应用与评判标准设计」。E7 新比较的数字和图表由其固定实验档案提供，历史案例不冒充版本比较结果。

本轮计划已完成：核对要求 → 仓外解包原证据 → 阅读公开正文、工具观察、状态与原评分 → 每轨选例 → 编排展示与提交清单。19 个不同案例覆盖 20 个展示用途；Intervention 的 I12 同时用于失败归因和评分分歧，两处不重复计入实验分母。

## 1. 证据与身份

下列四轨案例均来自 [E6 I48 证据包](../evaluation/artifacts/e6-completion-20260909/public-evidence.tar.gz)的 `formal113/`，固定 **Protocol 1.13 / 35e77cf**，真实 Hy3 Agent 与真实 Hy3 Judge，初态及教学材料由作者合成。原批 23 通过、18 不通过、7 无分，`formal=false`；本节只选取其中有分案例，完整分母及失败仍见[原结果 CSV](../evaluation/artifacts/e6-completion-20260909/final-cases.csv)。来源资格及 Runtime/Judge 不完整使原批未形成正式能力统计。

为使路径简洁，每例给出完整 Episode ID；以下模板中的 `{id}` 替换为该 ID 即为**精确包内位置**：

| 标记 | 包内路径 / 定位方式 |
| --- | --- |
| E | `formal113/runtime/episodes/{id}.json`；事实、公开正文、返回参数、实际工具结果、Guard、Operation、状态差异 |
| R | `formal113/rules/rules/{id}.json`；`checks` 按 `check_id` 定位 |
| J | `formal113/judge/judge-results/{id}.json`；`dimensions` 固定顺序 D1–D7 |
| A | `formal113/adjudicated/episodes/{id}.json`；原复核聚合结果 |
| 原响应 | `formal113/judge-attempts.jsonl`；按 `episode_id` 与 `attempt` 定位，保留 `public_response`、事实核验、响应摘要和计费票据 |
| 原内容复核 | `formal113/content-audit.json` 的 `rows[case_id=完整案例名]` |
| 原评分分歧复核 | `formal113/judge-content-audit.json` 的 `rows[case_id=完整案例名]`，以及 `formal113/semantic-reviews.json` |

下面 `T[n]`、`M[n]` 分别是 E 内 `observable_trace.tool_invocations[n]`、`observable_trace.model_calls[n]`，下标从 0 开始。分数写作「Judge 原始分 → 原复核最终分」；D 档位按 D1–D7 顺序列出，2 为该维满档。案例中的“复核同意/不同意”是本轮对原材料的内容复核，**没有另造七维分数或改写旧分**。原复核身份为 `primary_ai_reviewer`、`independent=false`；本轮也是开发协作中的复核，不属于独立盲标。 本稿的 19 组案例身份、原始/最终分数及 133 个维度档位已逐项与原 CSV 核对，76 个 Episode/Rules/Judge/聚合包内路径均实际存在，文档本地链接已检查。
