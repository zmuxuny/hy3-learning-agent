# DecisionBench：学习决策评测集

本集服务于 Learning Agent 的四类开放式决策：如何规划学习、何时提供帮助、如何验收成果、如何调整计划。输入包含用户要求、已有学习状态与可用材料；合理输出可以有多种，评价依据是约束、证据与实际效果。

## 实际应用任务与构造记录

这里保存两类材料。应用任务规定用户要求、已有状态和可用资源，让学习助手实际处理；构造记录则直接写出不同质量的助手回复、操作和结果，用于检查评测器是否能够辨别错误。

[应用任务清单](application/manifest.json)共有48项任务，规划、介入、验收、调整各12项。每项独立运行一次，产生一份真实决策记录，再评分一次。学习者条件由我们编写，不含真实学习者身份。全部任务按报告附录的A01—A48编号列在[完整目录](../../../评测用例目录.md)，每项同时链接任务文件和实际运行文件。

[三种质量的对照](method-validation/README.md)另选8个情境，每个编写处理正确、局部缺陷、严重错误三种版本，得到24份记录；各评分3次，共72次。例如，去重验收的三个版本分别正确退回并要求复测、退回但遗漏关键复测、虚称测试成功并接受作品。保持用户条件相同，才能把分数差异与具体行为联系起来。预设质量标签不传给评分模型。

这72次评分同时用于比较三种质量的好坏顺序，以及同一记录三次评分的波动。另有[8份评分操纵记录](adversarial/README.md)，在严重错误版本中追加术语和满分指令，保留原行为，各评1次。

[正常与严重错误对照](extensions/severe-validation-20260910/README.md)使用另一批12个情境，各编写正常、严重错误两份记录；24份各评3次，也得到72次。这里同时检查严重错误漏检和正常行为误判，材料与上一项72次实验不同。

[条件与工作量对照](extensions/condition-validation-20260910/README.md)用6个情境各编写正确、缺陷两份建议，各评3次，共36次，检查条件遗漏和工作量矛盾。后两类具体材料在评分方法固定后编写。

合计48＋24＋8＋24＋12＝116份待评记录，评分48＋72＋8＋72＋36＝236次，全部采用同一方法。前四部分的200次合并归档，条件检查的36次单独归档。一次评分包含核验内容、按七维给等级和计算分数，不是一次模型调用。全部材料的编号、具体要求、文件名与目录见[用例目录](../../../评测用例目录.md)，实验解释见[项目与评测报告](../../../第三阶段项目与评测报告.md)。

## 目录与来源

- `method-validation`：24份三档输出、公开证据及独立标签。
- `adversarial`：8份行为不变的评分操纵变体。
- `application/cases`：48个可执行情境。
- `application/resources`：固定教学材料。
- `application/manifest.json`：输入清单。
- `application/benchmark-release.json`：输入和工程协议的来源绑定。
- `extensions/severe-validation-20260910`：24份正常/严重输出及独立标签。
- 输入来源：`../decisionbench-v1.13-e6-final-test`；原始字节保留，应用运行的源码版本与输入绑定单独保存。

数据、构造脚本与项目采用同一仓库许可证。当前集与旧目录的关系见[上层索引](../README.md)。
