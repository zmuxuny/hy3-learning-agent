# 严重失败识别的新场景验证

这是DecisionBench的独立方法扩展，主体48个应用场景、24份三档输出及8份评分操纵对抗保持原版。

新增12个场景族，四类决策各3个。每族有正常、严重缺陷两份受控输出，共24份；各重复评分3次，共72个位置。输出由开发者构造，最终状态是题目给定的观察，不是实际产品运行。标签在`private-labels.json`中，评分请求只读取`suite.json`所指向的证据。

| 类别 | 新场景族 |
| --- | --- |
| 学习规划 | 备份脚本计划的采用权限、命令行参数练习的执行凭证、可访问性目标被替换 |
| 主动介入 | 取消订阅后的答题提醒、每日提醒次数上限、站内帮助被转成邮件 |
| 成果验收 | 中文字符的字节统计、分页修复后的新观察、图片签名校验的必需证据 |
| 计划调整 | 延后练习时保留批注、只调整指定项目、并发更新后的操作范围 |

方法第9版先固定为源码91bd043、摘要`b473189f42564de0401fe93aa1a9d2db30757ed002ebdde2322b932fbf8248b3`，随后编写此集合的具体场景与输出；构造脚本在ca4f2dc中保存。这里的“新/未见”指具体场景和输出未用于此前方法调试。缺陷机制有意围绕此次开发目标，不声称未见缺陷类型泛化或独立第三方测试。

正常对照包括合理等待、请求必要材料、授权内操作和新复测成功。严重输出覆盖实际越权、虚构执行和错误接受仍失败的成果。报告同时统计36次严重识别、36次正常通过及无分，不以一律拒绝获取高命中率。

构造命令（仓库根目录）：

```bash
PYTHONPATH=evaluation/src .venv/bin/python evaluation/scripts/build_quality_unseen_validation.py --output /tmp/new-family-inputs
```

[固定设计、完整评分与复算](../../../../artifacts/decisionbench-severe-validation-20260910/README.md)随独立实验归档。原始字段含义：`state_before`为用户条件及初态观察，`state_after`为给定最终观察，`result.user_visible_output`为被评助手回复。显式测试中的`expected`与`actual`分别为期望值和真实观察值；新状态中的测试记录替代对应初态测试。
